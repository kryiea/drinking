# Design: Coffee-First Recording Reset

## Product Direction
- 产品重心收敛为：`记录咖啡类 / 奶茶类摄入 -> 计算当前与睡前咖啡因残留 -> 帮用户形成更稳定的日常节奏认知`。
- 用户侧不再突出 AI 推荐，不做“帮你决定下一杯喝什么”的主叙事。
- 首版聚焦咖啡与奶茶两大高频饮品族群，其余饮品保留基础录入能力，但不再消耗主设计带宽。

## Information Architecture

### 首页
- 目标：一眼读懂，而不是阅读长解释。
- 固定模块压缩为 4 块：
  - 当前体内估算咖啡因
  - 今晚入睡时间点处的预计残留值
  - 快捷记录入口（最近一杯 / 常喝 / 语音 / 拍照）
  - 最近摄入时间线（最多 3 条）
- 不再展示 AI 卡片流；解释性内容下沉到分析页。

### 记录
- 目标：最快完成输入。
- 首屏优先级固定为：
  - 最近一杯 / 常喝
  - 语音输入
  - 图片识别 / 快速搜索
  - 主流品牌目录
  - 个人添加饮品
- 目录改为更紧凑的 list tile / chip 组合，不再使用大面积信息卡。
- 目录分区固定为：
  - 常喝
  - 主流咖啡
  - 主流奶茶
  - 我添加的饮品
- 目录 seed 首批只覆盖主流品牌与高频款式，避免早期目录过宽却不够深。

### 分析
- 目标：帮助用户理解身体影响，而不是输出泛建议。
- 核心图表固定为“咖啡因随时间衰减曲线”，并明确标出：
  - 每次摄入时间点
  - 当前时间点
  - 入睡时间点
  - 入睡时间点处的预计残留值
- 次级分析只保留最近 24 小时 / 7 天趋势，不在此阶段扩展复杂营养分析。

### 我的
- 目标：只保留真正需要用户管理的参数。
- 个人设置：
  - 目标入睡时间
  - 咖啡因代谢敏感度 / 半衰期
  - 常用默认份量或杯型
  - 常喝品牌偏好
- App 设置：
  - iCloud 同步状态
  - 通知与提醒
  - 首页 Widget 配置入口
  - 导入 / 导出
- 开发态或支持平台信息不再出现在用户侧主页面。

## Input Design

### 语音输入
- 语音输入定位为“快速录入入口”，不是开放聊天。
- 语音解析目标固定为结构化短句，例如：
  - “MANNER 燕麦拿铁一杯”
  - “下午三点冰美式大杯”
  - “霸王茶姬伯牙绝弦半糖”
- 解析流程：
  - 语音转文字
  - 本地 parser 提取品牌、饮品名、时间、规格、糖度等 token
  - 给出确认卡片
  - 一键确认写入
- 若解析不完整，回退到带关键词的目录搜索，而不是失败中止。

### 图片识别
- 保留本地 OCR 图片识别作为减负入口。
- 图片识别不替代语音和搜索，只作为并列的快捷操作。

## Catalog Strategy
- 目录设计从“信息很多的卡片”切换为“可扫读、可连续点击”的紧凑结构。
- `DrinkBrand` 与 `DrinkDefinition` 解耦，保证同一品牌下多款饮品能按列表快速浏览。
- `UserDrinkTemplate` 独立分区展示，并支持：
  - 复制官方饮品为个人版本
  - 自定义咖啡因 / 糖 / 杯量
  - 快速加入最近常喝
- 咖啡首批建议 seed：
  - 星巴克、瑞幸、MANNER、M Stand、Peet's、Blue Bottle
- 奶茶首批建议 seed：
  - 霸王茶姬、喜茶、奈雪、CoCo、茶百道、古茗、沪上阿姨

## Caffeine Metabolism Model
- 模型必须保持确定性和可解释，不使用黑箱推荐。
- 基础输入：
  - 每笔摄入时间
  - 每笔摄入咖啡因毫克数
  - 用户设定半衰期或敏感度档位
  - 用户设定入睡时间
- 结果输出：
  - 当前体内估算咖啡因
  - 入睡时预计残留值
  - 曲线 timeline points
  - 文本标签：安全 / 观察 / 易扰睡
- 计算逻辑应沉到纯领域层，保证 iPhone、Widget、Watch 与未来鸿蒙端可复用同一规则。

## Sync Architecture
- 推荐方案：`用户数据本地优先 + SwiftData 持久化 + CloudKit/iCloud 同步`。
- 调整原因：
  - 用户目标从“多端业务系统”转向“Apple 生态内无感记录”。
  - Watch 与 Widget 对本地可用、低延迟和系统整合要求更高。
- 同步边界拆成两层：
  - `UserDataStore`: 本地数据访问、查询、写入
  - `SyncProvider`: iCloud / future backend / none
- 第一阶段 Apple 生态以 iCloud 为主同步通路。
- 后端保留价值：
  - 品牌目录 seed 管理
  - 内部支持后台
  - 未来非 Apple 平台或跨生态账户体系的扩展缝
- 这意味着“服务端是真源”将从用户日志领域退到“目录与后台工具”领域。

## Apple Surface Plan

### Widget
- 首批 Widget 设计 3 个：
  - `当前咖啡因`：显示当前体内估算值与状态色
  - `今晚残留`：显示入睡点预计残留与入睡时间
  - `快捷记录`：直接记录最近一杯 / 常喝 2 杯
- Widget 必须可一眼读完，不堆文字。

### Watch App
- Watch 只做两件事：
  - 快速记录最近一杯 / 常喝
  - 查看当前体内估算咖啡因与今晚残留
- Watch 不承担完整目录管理和复杂分析。
- 需要同时规划：
  - watch quick add screen
  - current caffeine glance
  - 与 iPhone 的即时刷新

## Implementation Phases
1. 产品重置：
   - 去掉用户侧 AI 推荐文案与主入口
   - 重写首页 / 记录 / 我的信息结构
2. 咖啡优先目录：
   - 精简卡片
   - 引入品牌分区与个人添加分区
   - 完善 seed 数据
3. 快速输入：
   - 语音输入
   - 图片识别回退优化
   - 最近 / 常喝的真正一键写入
4. 身体影响：
   - 咖啡因曲线图
   - 入睡时间与残留标记
   - 设置页中的睡眠时间和半衰期参数
5. Apple 生态扩展：
   - iCloud 同步
   - Widget
6. Watch：
   - watchOS 快速记录与当前值查看
7. 后续路线：
   - 鸿蒙版领域模型迁移与同步策略评估

## Risks
- iCloud 优先会削弱“后端真源”的跨平台一致性，但能明显提升 Apple 生态体验。
- 语音输入如果不做约束，解析复杂度会快速失控，因此必须限定结构化短句和确认步骤。
- Watch 若过早承载复杂目录，会拖慢交付，应坚持“最近 / 常喝 / 当前值”最小集。
- HarmonyOS 适配不应在当前 change 内实现，只应为未来保留领域模型和同步抽象。

## Validation
- 领域单测：
  - 咖啡因曲线与半衰期计算
  - 入睡点残留值
  - 语音 parser
  - 图片识别匹配
- iOS UI 测试：
  - 最近一杯快速记录
  - 语音输入确认
  - 我的页设置睡眠时间后首页与分析即时刷新
  - Widget / Watch 关键快照
- 文档要求：
  - `agent.md`
  - 受影响 product/quality/ADR 文档
  - OpenSpec proposal/design/tasks/spec 必须同步
