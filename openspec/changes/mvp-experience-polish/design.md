# Design: MVP Experience Polish

## Review Scope
- `Onboarding`
- `首页`
- `记录`
- `分析`
- `我的`

## Page Audit

### Onboarding
- 当前优点：
  - 首屏结构简单，Apple 登录与离线体验入口清晰。
  - 视觉基础与主 app 风格一致。
- 当前问题：
  - 仍保留“可解释建议”文案，与 coffee-first 方向冲突。
  - 价值叙事更像上一版“健康解释 + AI”，不是“低负担记录 + 影响理解”。
  - 缺少对离线可记、个人节奏、同步方式的真实预期管理。
- 结论：
  - 将 onboarding 改成“快速记一杯 / 看今晚影响 / 记录可本地开始”的单一叙事。

### 首页
- 当前优点：
  - 顶部 summary card 已经具备“一眼看懂”的框架。
  - 快捷记录与最近时间线已收敛到核心内容。
- 当前问题：
  - 首屏模块数仍偏多，summary card 的标题、副标题、状态、指标、pill、按钮同时争抢注意力。
  - `今天结构` 与 `刚刚喝过` 都在表达“今天喝了什么”，信息边界还可以更清。
  - 部分文案仍偏解释态，不够像“ glanceable home”。
- 结论：
  - 首页应更像一个 glance dashboard：只保留风险判断、两个关键值、快捷操作、极简时间线。

### 记录
- 当前优点：
  - 四个快入口、品牌分区、个人饮品分区、Brew Lab 已具备较强产品雏形。
  - 语音与 OCR 都采用“先识别后确认”的正确边界。
- 当前问题：
  - 首屏操作足够多，但“主操作”和“次操作”的视觉权重还不够开。
  - 品牌目录和个人分区虽然已紧凑化，但不同 section 之间的节奏仍可以更统一。
  - 快速动作完成后的“继续记下一杯 / 返回首页 / 看影响”闭环仍然隐含在 toast 中，不够显性。
- 结论：
  - 记录页当前已接近 MVP 核心页，后续主要是做微交互、连续记录效率和 seed 深化，不需要推倒重来。

### 分析
- 当前优点：
  - 以咖啡因曲线为中心的页面目标清楚。
  - 当前值、入睡点、阈值、摄入点都已具备。
- 当前问题：
  - 图表下方补充文本仍稍显偏长。
  - “今日结构”与首页存在重复，未来更适合变成更少但更有解释力的比较视图。
  - 最近 24 小时条目对“哪杯最影响睡眠”的表达还不够强。
- 结论：
  - 分析页已具备可用性，下一轮优先做信息强化和图表阅读辅助，而不是继续加新模块。

### 我的
- 当前优点：
  - 睡眠时间、代谢档位、导出、本地开发连接都已接线。
  - 设置改动能即时反馈到首页和分析页。
- 当前问题：
  - `iCloud 路线`、`Apple Watch 规划` 仍是路线说明口径，不像真实设置。
  - 开发连接虽然已下沉，但仍与用户态设置混在一个页面层级。
  - 数据区只有导出，缺少“记录总数 / 最近同步 / 个性化资产”这种更贴近用户理解的摘要。
- 结论：
  - `我的` 需要从“路线说明页”变成“个人参数 + 数据状态 + 次级开发工具”结构。

## Iteration Plan

### Phase 1: Narrative Cleanup
- 重写 onboarding 价值叙事
- 清理首页与我的页中的规划态/AI 残留
- 调整页面标题、副标题和指标文案，压缩文字量

### Phase 2: Home And Profile Usability
- 首页只保留 1 个核心 hero、1 组快捷记录、1 条极简时间线
- 我的页拆成：
  - 个人节奏
  - 同步与设备
  - 数据动作
  - 开发工具（仅在可用时展示）

### Phase 3: Logging Flow Micro-UX
- 强化连续记录路径
- 优化品牌区、个人饮品区、最近一杯的视觉节奏
- 补“记录成功后下一步”显式动作
- 增强记录页的扫描效率：用户应能快速区分“最近刚记过的”“正在筛选的”“当前分区里有哪些”

#### Logging Feedback Detail
- 全局 toast 继续保留，负责告诉用户“已经写入成功、睡眠影响变化、同步状态”。
- 记录页在成功写入后，需要额外出现一个短时 next-step rail，放在快操作区之后、目录之前。
- 这个 rail 只在 `记录` 页展示，并且只在成功写入后的短时间内显示。
- rail 至少提供 3 个明确动作：
  - `再来同款`
  - `看今晚影响`
  - `继续搜目录`
- `继续搜目录` 的作用是清空搜索和筛选态，让用户马上开始下一次选择，而不是继续停留在刚才的上下文里。

#### Logging Scanability Detail
- 在无筛选态时，记录页应提供一个轻量的最近记录条，帮助用户直接复用刚喝过的几杯。
- 筛选区应能一眼看出当前是否处于筛选态，并支持一键清空。
- 目录分区应显式展示数量或分区感，降低“都是一串卡片”的阅读疲劳。

### Phase 4: Insight Readability
- 优化图表辅助说明
- 明确标出最影响入睡的一杯
- 为未来 Widget / Watch 共用可视指标建立稳定表达

## Validation
- `swift test`
- `xcodebuild -project ios/Yinzhi.xcodeproj -scheme Yinzhi -destination 'platform=iOS Simulator,id=<simulator-id>' build`
- 逐页人工检查：
  - Onboarding 不再出现 AI 主叙事
  - 首页首屏在不滚动时可完成“当前风险 + 记录入口”识别
  - 我的页设置层级清楚，开发工具不抢主路径
  - 记录成功后，记录页存在可点的下一步动作，而不是只剩被动 toast
