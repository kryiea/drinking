# Proposal: Record Selector And Calculator Refresh

## Why
当前记录页已经具备语音、拍照、相册、目录和计算器能力，但页面组织仍偏功能面板。用户在进入记录页后，需要先理解模块，再开始寻找要记的饮品，这和高频记录产品应有的“选中就记”节奏并不一致。

当前咖啡因计算器则仍是表单式页面。它能工作，但更像开发工具而不是消费级工具页，缺少明确的冲煮方式主视觉、参数卡节奏和可复用结果动作。

## What
- 把记录页重构成更轻的“选择器”结构：搜索、品牌圆标带、快速入口、轻量列表。
- 把最近记录和个人饮品改为更薄的 row，而不是信息密度偏高的功能卡。
- 把咖啡因计算器重构为“冲煮方式主视觉 + 参数卡片 + 大结果 + 双 CTA”的工具页。
- 为计算器引入可测试的本地估算模型，保证后续 Watch / Widget 能复用同一套规则。

## Success Criteria
- 用户进入记录页后，无需阅读长文案，也能立即理解“搜一杯 / 切品牌 / 点一行记录”。
- 品牌目录与个人饮品都使用更轻的列表密度，连续浏览效率高于当前版本。
- 咖啡因计算器在首屏就能看见冲煮方式、关键参数和估算结果。
- 计算器估算逻辑具备可运行测试，不再完全埋在视图里。
