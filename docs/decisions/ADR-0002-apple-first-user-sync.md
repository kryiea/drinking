# ADR-0002: Apple 生态内用户数据改为本地优先与 iCloud 同步

## 状态
Superseded by ADR-0003

## 背景
产品方向正在从“前后端分离 + 服务端真源 + AI 建议”收敛到“咖啡优先的日常摄入记录 + 咖啡因影响理解”。新的重点强调：
- iPhone 内快速记录体验
- Widget 与 Watch 的系统级可达性
- 无登录或弱登录场景下的低摩擦同步
- 未来仍需给鸿蒙版保留工程后路

## 决策
- 用户日志与个人设置的主存储改为 Apple 生态内本地优先。
- 本地持久化继续使用 SwiftData。
- Apple 生态内同步优先使用 CloudKit / iCloud。
- 后端从“用户日志真源”退到“品牌目录、内部后台和未来跨平台同步扩展缝”。
- 同步边界新增 `SyncProvider` 抽象，避免把 CloudKit 写死在页面层或领域层。

## 结果
- iPhone、Widget、Watch 能获得更顺滑的本地可用与低延迟体验。
- 记录链路可摆脱账号态和远端网络成功率的强耦合。
- 未来如果鸿蒙版需要跨生态数据共享，仍可在 `SyncProvider` 层接回服务端方案。
- 当前 iOS 壳层已经按该方向完成 phase 1：首页、记录、分析、我的转为本地优先的咖啡因记录体验，用户侧 AI 推荐从主链路撤出。

## 代价
- 当前 ADR-0001 中“服务端作为业务真源”的表述将不再适用于用户日志领域。
- 未来跨 Apple / 非 Apple 生态的数据一致性会变成一个单独议题。
- CloudKit、Widget、Watch 的交付复杂度会替代一部分现有后端复杂度。

## 后续说明
- 本 ADR 已经被更广义的“本地优先、后端辅助”架构路线吸收。
- 当前正式架构请以 `ADR-0003` 为准。
