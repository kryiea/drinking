# ADR-0003: 本地优先应用架构与后端辅助角色

## 状态
Accepted

## 背景
项目当前的产品目标已经收敛为：
- 在 iPhone 内尽可能低负担地记录咖啡 / 奶茶摄入
- 本地即时计算当前咖啡因与入睡残留
- 在 Apple 生态内优先保证无网可用和弱登录可用
- 为 Widget、Watch 和未来 HarmonyOS 研究保留工程后路

仓库中虽然已经逐步落地了 `UserLocalSnapshot + SyncProvider + iCloud` 路线，但长期文档仍遗留“服务端真源”的旧叙事，导致架构定位不一致。

## 决策
- 当前产品主系统定义为：`iOS App + 本地持久化 + 本地确定性计算`
- 用户日志、个人设置、个人饮品模板在 Apple 生态内以本地数据为主真源
- Apple 生态内同步继续通过 `SyncProvider` 隔离，优先使用 iCloud / CloudKit，`LocalOnly` 必须继续是合法模式
- 后端保留为辅助系统，负责：
  - 品牌目录与 seed 管理
  - support / admin
  - 可选导出与远程任务
  - LLM / 外部服务适配
  - 未来 Android / Web / HarmonyOS 的跨生态同步接入缝
- 当前主记录链路不得以后端可用性作为硬依赖
- Typed client、API contract 和后端代码骨架继续保留，作为辅助远程能力与未来扩展的稳定边界

## 结果
- 产品主体验与当前实现一致：无后端也能完成记录、查看和设置
- Apple 生态内的低延迟和弱网可用性成为默认能力，而不是额外 fallback
- 后端仍然有明确价值，但从“真源系统”转为“辅助系统”
- 未来若需要跨生态统一账户和跨端数据一致性，可以在 `SyncProvider` 边界重新引入服务端真源方案，而不必推翻当前本地架构

## 代价
- 未来跨 Apple / 非 Apple 生态的数据一致性会成为独立设计议题
- 部分远程能力将天然变成“增强项”而不是“主路径的一部分”
- 需要更严格地区分“本地主链路”和“后端辅助链路”的产品边界

## 替代方案
- `继续保持服务端真源`: 不符合当前离线优先和 Apple 生态优先目标，会让核心记录链路重新依赖网络和账号态
- `完全移除后端`: 会削弱品牌目录管理、support/admin、远程适配和未来跨生态扩展能力

## 关系说明
- 本 ADR 取代 `ADR-0001` 中“服务端作为业务真源”的当前效力
- 本 ADR 吸收 `ADR-0002` 中关于用户数据本地优先与 iCloud 同步的方向，并把它提升为仓库层的正式架构路线
