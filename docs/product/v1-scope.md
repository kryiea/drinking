# 饮知 v1 范围说明

## 核心价值
帮助用户快速记下咖啡、奶茶等高频饮品摄入，并直接理解这些摄入会怎样影响当前状态和今晚入睡。

## 当前用户路径
1. 通过语音、拍照、相册、最近一杯或紧凑目录，快速记下一杯。
2. 在首页一眼看到当前体内估算咖啡因、入睡时预计残留，并从底部主动作进入记录。
3. 在分析页查看咖啡因随时间变化的时间视图，并对照入睡时间点。
4. 在我的页面通过多级设置调整入睡时间、代谢档位、同步与数据。

## 第一版包含
- 咖啡 / 奶茶优先的品牌化目录
- 紧凑品牌分区：主流咖啡、主流奶茶、个人添加饮品
- 最近一杯与常喝的一键记录
- 本地 OCR 图片识别辅助录入与关键词回退
- 结构化语音输入与候选确认
- 手冲 / 咖啡机计算入口
- 当前体内咖啡因估算、入睡点残留和睡眠状态标签
- 咖啡因时间视图、摄入事件点和入睡时间标记
- 本地优先缓存与离线记录
- `UserLocalSnapshot + SyncProvider` 的 iCloud 同步缝
- 多级设置页：睡眠时间、代谢档位、同步与数据、我的饮品、开发连接
- 后端辅助能力：品牌目录、可选导出接口、开发者 support 平台与目录 / LLM 联调后台

## 当前 UI 方向
- 首页是“今晚状态页”，固定由状态主卡、紧凑时间视图和底部浮动 `记一杯` 组成。
- 首页主卡优先展示当前体内咖啡因、入睡时预计残留和状态色，不再堆长解释。
- 记录页固定结构是：上方搜索与快速入口，下方品牌目录与轻量列表。
- 记录入口保留 `语音 / 拍照 / 相册 / 计算器 / 最近复用`，但全部降为 selector 风格的轻量 pill，不再抢主体信息。
- 品牌目录使用小 logo rail，优先让用户通过品牌快速缩小范围，而不是阅读品牌名 tab。
- 记录目录使用更紧凑的 row，而不是信息很重的大卡片；`最近` 与 `我的饮品` 固定为前置 section，品牌识别主要交给 logo。
- 咖啡因计算器改为“冲煮方式主视觉 + 大结果 + 参数卡 + 双 CTA”的答案页，首屏先看到估算值，再继续微调参数。
- 计算器插图必须优先服务辨识度，至少让意式机、手冲和胶囊三种方式在一眼内可区分，不依赖长文案补解释。
- 默认 starter pack 预置 `瑞幸`、`星巴克`、`库迪`、`喜茶`、`霸王茶姬`、`一点点` 的代表饮品，打开就能直接记录。
- 分析页以咖啡因曲线为核心，不再以 AI 解读为核心。
- 我的页只保留个人设置、App 设置、数据管理和次级开发连接。
- 当前 polish 原则是：每个一级页面只强调一个核心任务，不让 roadmap、开发态或长文案抢走首页面主目标。
- 视觉系统默认跟随系统浅色 / 深色模式，状态色、卡片层级和关键数字在两套外观下都必须保持足够对比度。
- 当前架构原则是：本地数据主真源，后端增强但不阻塞主记录链路。

## 第一版不包含
- 用户侧 AI 推荐主叙事
- 聊天式 AI
- 社区、专家咨询、企业版、订阅付费
- 条码和实时取景识别
- 已上线的 iCloud / Widget / Watch 正式 target
- HarmonyOS 实现

## 后续阶段
- `Current Polish`: onboarding / 首页 / 我的页的叙事收口，记录页与分析页微交互完善
- `Phase 2`: iCloud capability 真同步验收、Widget、Watch app
- `Phase 3`: 品牌 seed 扩充、个人饮品管理深化、更多结构化 parser
- `Later`: HarmonyOS 适配和跨生态同步策略
